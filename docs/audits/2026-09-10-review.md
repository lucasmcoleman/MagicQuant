# MagicQuant audit and review — 2026-09-10

## Assessment

MagicQuant has a strong research and engineering core: streaming GGUF output,
canonical upstream quantization facts, empirical measurement, explicit failure
provenance, and a substantial regression suite. Its main weakness is trust at
boundaries: a valid-looking header, cached measurement, installed package, or
downstream stage can promise more than the checks establish. More quantization
schemes are a lower priority than making existing results reproducible and
verifiably connected to the artifact a user downloads.

This audit covers the tracked Python package, tests, development/release
configuration, and integration with sibling Foundry. It combines code inspection,
baseline suites, synthetic GGUFs, real library differential tests, and built-wheel
checks. It is not an exhaustive model-architecture certification, penetration
test, or GPU performance benchmark. No existing model outputs, services,
credentials, or installed development environments were changed.

## What is good

1. **Canonical facts and independent references.** `quant/ggml_facts.py` derives
   type facts from `gguf`; ctypes encoder tests compare against actual libggml,
   and writer tests use the upstream reader. These catch errors that matching
   in-house encoder/decoder bugs could conceal.
2. **Memory-conscious architecture.** The writer resolves sizes and offsets
   before a streaming data pass; temporary output publication and fallback
   provenance reduce corruption and make large models feasible on this machine.
3. **Honest size semantics.** Tier bands, structural quantization constraints,
   imatrix requirements, and fork-only formats are explicit. Measured search
   distinguishes failure from a successful measurement with zero change.
4. **Useful characterization tests.** Seeded search fixtures, checkpoint resume
   tests, metadata type round-trips, QAT differential tests, and workflow parsing
   guards capture real incidents. The baseline main suite passed 1,227 tests
   with 20 skips.
5. **Research transparency.** QAT control-arm comparisons and disclosures of
   frozen-mode limitations are much more useful than an unexplained headline
   perplexity number.

## Implemented findings

### P1 — Non-default GGUF alignment could read or emit incorrect weights

`gguf/reader.py:open` always aligned tensor data to 32 bytes. The writer also
uses 32-byte padding, but copied a source's `general.alignment` unchanged.
Consequently a legitimate 64/256/4096-byte-aligned source could be read at the
wrong offset, and a generated file could advertise a layout it did not use.

The reader now honors and validates the source alignment; the writer normalizes
the output metadata to its actual layout. Synthetic files created by upstream
`gguf.GGUFWriter` are repacked and checked with upstream `GGUFReader` for exact
tensor values. See `tests/test_reader_integrity.py`.
The alignment contract is defined by the upstream
[GGUF specification](https://github.com/ggml-org/ggml/blob/master/docs/gguf.md).

### P1 — A failed header parse could become a successful cached reader

`GGUFReader.open` set `_opened=True` before parsing and mutated public state
incrementally. After a failure, later accessors could return partial metadata
without retrying or raising. Parsing is now transactional: only a complete
header sets reader state. Length-prefixed reads, record counts, dimensions,
array nesting, versions, alignment, and tensor starting offsets receive bounds
checks. An invalid version-zero test fixture was replaced with a real v3 header.

This is header validation, not a complete hostile-file verifier. Full tensor
extent/overlap validation and parser fuzzing remain recommended.

### P1 — Release wheels omitted the default calibration corpus

The original wheel contained no `magicquant/data/calib_corpus.txt`; editable
installs hid the omission. Explicit package data now includes the corpus.
`tools/check_wheel.py` installs a built wheel into a temporary target and checks
the CLI and corpus outside the source tree, with isolated Python import lookup.
CI and release workflows run this check. Both the original failure and corrected
wheel were reproduced locally. The mechanism follows the upstream
[setuptools package-data documentation](https://setuptools.pypa.io/en/latest/userguide/datafiles.html).

### Development commands

`make` targets prefer a local virtualenv and accept `PYTHON=...`; `make lint`
matches the required Pyflakes gate. This avoids this machine's misleading bare
Python shim and makes the same commands usable in review worktrees.

### P1 — Search compared distortion values on inconsistent scales

`v2/sensitivity.py` scaled sampled quantized errors to the whole tensor but
omitted that scaling for F16. A 2-of-16-row fixture understated F16 error by 8×.
Per-expert importance weights were also missing from F16 error and the reference
norm; a small MoE fixture understated error by 50.5×. These values directly
influence precision allocation. The metrics now use consistent sampling and
expert weighting. Distortion-table version 2 invalidates affected cached values.

### P1 — Failed references and missing choices could mislead allocation

When a cumulative all-aggressive reference failed, `v2/calibrate.py` interpreted
the remaining leave-one-group-high probes as single-group probes and labeled
them measured. It now preserves cumulative semantics, uses the existing explicit
imputation policy, and reports the failed reference. `_build_units` also refuses
unknown fixed-tensor sizes or tensors with no valid choices: silently omitting
those tensors understated bytes while the writer still emitted their weights.

### P1 — Default calibration and evaluation could use the same corpus

Both defaults can resolve to the bundled text when a separate evaluation corpus
is unavailable. v2 had no overlap check; v1 checked only explicit calibration
against an already-pinned evaluation path. Both now compare effective defaults
and explicit paths, including symlinks and hardlinks, before capture. v1 retains
its logged unweighted fallback; v2 rejects the configuration. Choose separate
corpora to retain imatrix. This detects shared file identity, not duplicated text
or semantic overlap between datasets.

The search changes have CPU regressions in `tests/test_v2_audit_regressions.py`
and `tests/test_allocation_and_corpus_guards.py`. The proposed cases failed on
the previous implementation; existing characterization cases remain checked.

## Cross-project findings requiring the next design pass

| Priority | Finding | Recommended acceptance criterion |
| --- | --- | --- |
| P1 | Foundry QAT produces adapters but its following MagicQuant stage does not consume them. | An explicit QAT merge/handoff records the exact base identity and per-tensor configuration; a test proves the generated weights differ by the intended adapter delta. |
| P1 | Foundry source selection prefers existing REAP/Heretic directories over newer merged output. | Every stage consumes a named artifact from a run manifest; an old optional-stage output cannot override the current run's selected source. |
| P1 | Tracked publishing criteria are not an enforced end-to-end release gate. | A release plan links each actual file digest to its band/budget, measured quality, throughput, source, and decision; only approved entries are uploaded. |
| P1 | Cache identity is weaker than complete experiment identity. | Cache keys record relevant model, tokenizer, corpus, backend, algorithm, and objective identities; changed inputs invalidate only affected computations. |
| P2 | Nominal budgets, predicted weights, actual GGUF bytes, and runtime memory are different quantities. | Show weights, metadata/padding, KV cache, context, and memory headroom separately; prove final-file budget enforcement on synthetic boundary cases. |

Specific unresolved MagicQuant findings:

- **P1, cache identity:** `v2/sensitivity.py:_model_identity` returns the same
  all-unknown identity for distinct safetensors directories. Its sampled imatrix
  hash misses changes outside sampled indices. Probe conditions in
  `v2/calibrate.py` omit corpus content and backend identity. v1 resume also
  compares corpus paths without their content. Use complete, versioned experiment
  identities before treating cache hits as trustworthy.
- **P2, approximate optimization:** `v2/allocate.py` uses a greedy solution and
  local polish, which cannot guarantee the global optimum. With A choices
  `(1 byte, loss 6)/(4 bytes, loss 0)`, B choices
  `(1 byte, loss 5)/(3 bytes, loss 0)`, and budget 5, it returns loss 6 at 4 bytes;
  loss 5 at 5 bytes is feasible. Add exact small-instance reference tests and
  consider swap-based improvement or a bounded solver. The allocator docstring
  and README now describe the approximation without an optimality guarantee.
- **P2, budget and failure contracts:** `v2/resolve.py` counts tensor payload,
  excluding GGUF metadata and padding. Final anchors record actual bytes without
  enforcing a strict final-file cap. When every anchor fails, `v2/search.py`
  raises before persisting the results file mentioned in its error. Reserve
  serialization overhead, verify actual size, and persist failure diagnostics.

## Improvements and missing features

- **Reproducible experiment manifests.** Record immutable source/dataset revisions,
  corpus hashes, tokenizer/template identity, libggml/llama.cpp build identity,
  seed, objective, hardware, context length, thread/offload settings, and file
  hashes. Current local size/mtime fingerprints are change detectors, not content
  authentication. Support comparison and cache invalidation from that manifest.
- **Evaluation beyond perplexity.** Add held-out tool-call/schema validity,
  execution correctness, long-context behavior, multilingual coverage, and
  generation latency/memory tests. Separate calibration, search selection, and
  final evaluation sets; retain QAT control arms. Repeat measurements and report
  uncertainty: a fixed noise margin is not a confidence interval.
- **Architecture contract matrix.** Maintain tiny reference conversions for
  supported architectures, tokenizer families, MoE layouts, and fork formats.
  New upstream names should trigger a differential validation task, not imply
  numerical compatibility. Unsupported formats should fail clearly.
- **Resource planning.** Add disk-space estimates/reservations, interruption-safe
  checkpoints, retention policies, and an output-directory lease. CPU sampling
  and memory estimates should be tested on representative large shapes without
  allocating real model-size fixtures.
- **Portable installation.** Separate a lightweight planning/inspection surface
  from platform-dependent encoder/training environments. Pin tested backend
  revisions in containers; the current Docker build tracks llama.cpp's branch
  head. Test both installed artifacts and compatible dependency sets, including
  the supported Python floor.
- **Maintainability.** Split orchestration by stable responsibilities, replace
  implicit dictionaries with versioned boundary schemas, and favor behavioral
  tests over source-string checks. Consolidate obsolete documentation rather than
  adding another competing description of current behavior.

## Questions worth considering

- Can a downloadable artifact prove exactly which source, adapter, search, and
  evaluation produced it after intermediate files are deleted?
- Is the best perplexity model also best at the tool-use or coding tasks users
  actually run, and does that hold across context lengths?
- Can two clients or processes write the same run, or two jobs reserve the same
  unified memory, without knowing about each other?
- Are source-model code execution and calibration-data provenance explicit
  operator choices? Are private training examples ever published implicitly?
- Can a failed or restarted job distinguish "not measured", "failed", "stale",
  "predicted", and "verified" all the way through the model card?
